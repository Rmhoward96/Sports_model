**Goal:** Replace the sim's season-average usage with a per-week active-roster usage model (depth charts + recent recency-weighted usage renormalized over the active set), fix QB→starter attribution, and re-gate on propable players — iterating to shippable calibration.

**Architecture:** New `sportsmodel.sim.nfl.usage` (pure) feeding `inputs.build_spec`; `generate_sim_nfl` + `backtest_sim_nfl` fetch/apply per-week depth charts, snaps (bridged pfr↔gsis), and per-week injuries. Kernel unchanged except tuning constants. Builds on the dormant `sim-nfl-engine` branch.

**Tech Stack:** Python, numpy, pandas, nfl_data_py, pytest, uv.

**Spec:** docs/superpowers/specs/2026-09-18-nfl-props-b2-design.md

## Global Constraints

- **NFL only.** Builds on branch `sim-nfl-engine` (B engine, dormant). Do not touch A/desk/+EV/CFB/MLB, and do not activate B (no migration, no workflow enable).
- **Leakage-free:** usage SHARES/EFFICIENCY come only from games strictly before (season, week). The target-week DEPTH CHART and per-week INJURY report are pre-game info and MAY be used to define who's active (that's what you'd know before kickoff) — but never post-game stats.
- **Pure** usage/aggregation (no IO); IO only in fetch wrappers + scripts.
- Reuse existing `PlayerInput`/`NflGameSpec`/kernel; the kernel already consumes `ypr` (B.1).
- Test + commit per task; match style.
- nflverse columns: depth_charts(`season,week,club_code,depth_team,position,gsis_id,full_name,football_name`); snap_counts(`season,week,team,player,pfr_player_id,offense_pct`); ids(`gsis_id,pfr_id`); weekly(`player_id,recent_team,position,season,week,targets,carries,receptions,receiving_yards,rushing_yards,passing_yards,receiving_tds,rushing_tds,passing_tds`); injuries via `sportsmodel.nfl.injuries_nflverse` shape `{abbrev:[{player,status,...}]}` (also import_injuries per-week for backtest).

### Task 2: `active_usage` — per-week active-roster usage (the core)

**Files:** `usage.py`; Test `tests/sim/nfl/test_usage_active.py`.

**Interfaces — Produces:**
`active_usage(team, upto_season, upto_week, depth_df, weekly_df, snaps_df, pfr2gsis, injuries_out_names, n_recent=5) -> tuple[list[PlayerInput], str|None]` returning (active PlayerInputs, starting_qb_gsis_id). PURE.

Logic:
- **Active set:** rows of `depth_df` for `club_code==team, season==upto_season, week==upto_week`, offensive skill positions (QB/RB/WR/TE), keyed by `gsis_id`; keep starters + rotation (all listed depth_team values for those positions). Drop any whose `full_name`/`football_name` matches `injuries_out_names` (case-insensitive).
- **Shares/efficiency:** from `weekly_df` rows strictly before (upto_season, upto_week), recency-weighted over the last `n_recent` games per player (weights e.g. linearly or exponentially decaying). Compute each active player's recent targets/carries/receptions/yards/TDs; `target_share`/`carry_share` = player recent targets/carries ÷ sum over the ACTIVE set (renormalized over active only — this kills dilution); `ypr`=rec_yards/receptions, `ypc`=rush_yards/carries, `catch_rate`=receptions/targets, `td_share`=player tds ÷ active-set tds. Guard all /0.
- **Cold start** (active player with no recent usage — rookie/returnee): assign a small depth-position prior share (documented defaults by position+depth_team) so they're not zero but don't dominate.
- **Starting QB:** the active QB with `depth_team` minimal (QB1); tiebreak by most recent attempts. Return its gsis_id. **Ruling C1:** the returned active set must contain exactly ONE `pos=="QB"` PlayerInput — the QB1, with `player_id` = its gsis_id — so downstream kernel attribution (which picks the passer as the sole/only QB) lands `pass_yds` on QB1 deterministically. Drop backup QBs from the active set.
- Snap `offense_pct` (bridged via `pfr2gsis`) MAY weight rotation shares; if a snap row can't be bridged, fall back to weekly-usage share (document).

- [ ] **Step 1: failing tests** (fixtures): OUT player excluded from active set; shares renormalize to ~1 over the ACTIVE set (not full roster); a high-recent-usage active player gets a high share; recency weighting favors recent games; QB1 returned by gsis_id; leakage — a row at/after (upto_season,upto_week) is excluded from shares; cold-start player gets a nonzero prior, not a crash.
- [ ] Steps 2–5 (implement; commit `feat(sim/nfl): per-week active-roster usage model`).

Keep the existing `build_spec` for back-compat/tests; add the usage-based path. **Ruling B1:** the passed `home_players`/`away_players` are ALREADY injury-filtered and renormalized-over-active by `active_usage` — do NOT re-drop injuries or re-renormalize here. **Ruling C1:** each side's players already contain exactly one `pos=="QB"` (the QB1 whose player_id is the qb gsis), so kernel attribution lands `pass_yds` on QB1 with no kernel change; `home_qb_gsis`/`away_qb_gsis` are threaded for assertion/pairing convenience.
