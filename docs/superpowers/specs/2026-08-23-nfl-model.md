# NFL model — game lines + player props (Week-1 launch)

**Date:** 2026-08-23
**Status:** Approved design (pre-plan)
**Component:** new `src/sportsmodel/nfl/` package + producers; multi-sport
parameterization of `scripts/ingest_odds.py`, `scripts/generate_board.py`,
`scripts/grade_results.py`; front-end `app.js` (NFL logos/filters).

## Problem & goal

The MLB pipeline (predictions → best-book board → CLV-graded track record → Blue Edge
front-end) is live and self-running. Extend it to **NFL**, live for **Week 1 (~Sept 10,
2026)**, covering **game lines and a focused set of player props**. Props are the priority:
NFL game lines are among the sharpest markets in sports (little edge), while player props
are softer and the primary +EV opportunity.

The serving layer (`board_picks`, `picks`, track-record views, front-end) is already
`sport`-aware and reusable. The new work is a sport-specific **model + data pipeline**, plus
**parameterizing three MLB-hardcoded producers by sport**.

## Decisions (settled)

- **Game-line model:** hybrid **market-shrunk Elo** — a margin-of-victory Elo (last-season
  carryover) blended toward the current market line by a weight that decays over the season,
  so early weeks (no 2026 data) stay sane and independence grows as data accumulates.
- **Data:** **nflverse (`nfl_data_py`)** for history/rates/backtest/grading; **ESPN public
  API** for the live weekly schedule, final scores, and game-day inactives.
- **Props (Week 1):** pass yards, pass TDs, receiving yards, receptions, rush yards, rush+rec
  yards, anytime TD (scoring handled by anytime-TD only — no separate rush-TD/rec-TD markets)
  — modeled usage × efficiency, game-script-adjusted, injury-aware.

## Scope / non-goals

- **In:** NFL game lines (ML/spread/total) + the nine prop markets; nflverse+ESPN pipeline;
  Elo + total model + prop model; multi-sport refactor of the three producers; NFL front-end
  logos/filters (already scaffolded).
- **Out (for now):** low-liquidity props beyond the nine (kicking, tackles, longest-
  completion, 1st/last TD, INTs); NBA; live/in-game; changing the MLB model.

## Data pipeline (`src/sportsmodel/nfl/`)

- **Historical (nflverse, committed snapshots — mirrors the MLB committed-assets pattern):**
  - `import_schedules()` → game results (season, week, home/away, scores) for ~10 seasons →
    Elo training + backtest + last-season final ratings for carryover.
  - `import_weekly()` → weekly player stats (pass att/yds/TD, targets, receptions, rec yds/TD,
    carries, rush yds/TD) → prop volume/efficiency rates + prop backtest + player grading.
  - `import_rosters()` / depth charts → who plays which role; map book player names → ids.
  - `import_injuries()` → weekly injury/inactive status.
  - Snapshots committed as parquet under `assets/nfl/` so CI runs without live pulls.
- **Live (ESPN public API):**
  - Weekly **schedule** (upcoming games, kickoff times) → producer input + `game_pk` scheme.
  - **Final scores** → game-line grading.
  - **Game-day inactives** → exclude/re-route props on OUT players (nflverse injuries can lag).

## Game-line model

- **Elo (margin-adjusted, FiveThirtyEight-style):** update after each final game with a
  margin-of-victory multiplier; home-field ≈ +2.5 pts (~+65 Elo). **Preseason carryover:**
  regress last season's final Elo toward 1500 (≈75/25). Expected margin =
  (elo_home − elo_away)/25 + HFA (points).
- **Total model:** team points-for / points-against per game (season-to-date, shrunk to the
  league average early) → expected total = home-offense-vs-away-defense + away-offense-vs-
  home-defense.
- **Market shrinkage (the "sane early" mechanism):** blend model expected margin/total toward
  the **current market** spread/total with weight `w(week)` decaying ≈0.75 (Wk1) → ~0.35
  (Wk8) → floor ~0.2. Applied at prediction time from the latest captured NFL odds.
- **Distributions:** margin ~ Normal(exp_margin, σ_margin≈13.2); total ~ Normal(exp_total,
  σ_total≈10). Discretize into the existing `margin_dist`/`total_dist` pmf format. win_prob =
  P(margin > 0). σ's and `w(week)` are fit by a **backtest on past seasons** before launch.

## Prop model

- **Volume** per active skill player: project pass attempts / carries / targets from
  **last-season per-game rates, regressed to role/position baselines**, then **adjusted by
  game script** — the game line's implied team total + spread shift pass/run mix and pace
  (favorites run more late; underdogs throw more). This is what gives Week-1 signal with no
  2026 data.
- **Efficiency:** yards/attempt, catch rate, yards/reception, TD rates from last-season/career,
  shrunk to position baselines.
- **Distributions per market → P(over) at the book line → EV** (reuses `prop_predictions.dist`
  + `grade_pick`):
  - Yardage (pass/rec/rush, rush+rec): Normal(mean = volume × efficiency, market-specific σ).
  - Counts (receptions): Negative Binomial.
  - Pass TDs: Poisson/Binomial on expected passing TDs → P(over 0.5/1.5/2.5). **Anytime TD**
    = P(≥1 TD) = 1 − P(0), from expected rush+rec TDs. TD markets are noisier → looser
    calibration expected.
- **Player universe:** projected starters/skill players per team from depth charts, **filtered
  to not-inactive**; match to book-offered props by player name (same approach as MLB).
- **Injury/inactive handling (required):** exclude OUT/inactive players; when a starter is
  out, bump the backup's projected volume via the depth chart. At minimum, never post a prop
  for an inactive player.
- **Odds-API market keys:** `player_pass_yds`, `player_pass_tds`, `player_reception_yds`,
  `player_receptions`, `player_rush_yds`, `player_rush_reception_yds`, `player_anytime_td`.
  Verify exact availability during P0 odds capture.

## Multi-sport parameterization (shared refactor — also sets up NBA)

The serving tables/views/front-end are reusable; three producers are MLB-hardcoded and become
sport-aware:
- **`ingest_odds.py`** — add NFL sport keys (`americanfootball_nfl`) for game lines + the prop
  markets; capture into `odds_snapshot`. Add an **NFL event → schedule `game_pk` matcher**
  (the NFL analog of MLB's commence-time/team matching) — a real integration piece.
- **`generate_board.py`** — replace the hardcoded `sport='mlb'`, MLB prop-market list, and MLB
  calibration keys with per-sport config; run an NFL pass writing `sport='nfl'` rows.
- **`grade_results.py`** — add an ESPN results/box-score fetch (`grade_pick` for
  ML/spread/total and over/under props is already generic); route by sport.

## Producers

- **`scripts/generate_nfl.py`** — for each upcoming ESPN game: compute Elo/total expected
  margin/total, shrink toward the latest market line, build `margin_dist`/`total_dist`/
  `win_prob`; project the active player universe → prop distributions; write `game_predictions`
  + `prop_predictions` tagged NFL (`model_version="nfl-elo-v1"` / `nfl-props-v1`). Scheduled
  weekly (and refreshed as inactives/lines firm up before kickoff).

## Calibration

- Backtest on past seasons to set σ_margin/σ_total and the `w(week)` shrinkage curve, and to
  fit per-market prop calibration (Platt on P(over) + loc/scale on the yardage distributions),
  stored in `assets/calibration.json` under NFL keys. TD markets calibrated but expected loose.

## Front-end

- Add an NFL `TEAM_ABBR` map + ESPN NFL logo path in `app.js`; the NFL page, nav, and market
  filters already exist. Board/track-record render NFL rows via the existing `sport` column.

## Acceptance / launch bar (Week 1)

- NFL game lines + the seven prop markets appear on the board with best-book prices, EV, and
  the +EV-or-pass gate; predictions are **sane early** (small deviations from the market on
  game lines; plausible player projections).
- Injured/inactive players never get a posted prop.
- Grading runs off ESPN finals + player box scores → `picks` → track record, filterable by
  league.
- No regression to the MLB pipeline (the sport parameterization is additive).
- Backtest shows the game-line shrinkage behaves (no wild early disagreements) and prop
  calibration is reasonable on the yardage markets. Beating CLV is the season-long judge, not
  a launch gate.

## Phased build (each its own spec→plan→TDD)

- **P0 — multi-sport plumbing:** parameterize `ingest_odds`/`generate_board`/`grade_results`;
  NFL odds capture (game lines + prop keys) + NFL `game_pk` matching; verify prop-market
  availability.
- **P1 — data + Elo:** nflverse ingest (schedules/weekly/rosters/injuries) as committed
  snapshots; margin-adjusted Elo + carryover; ESPN schedule/scores/inactives adapters.
- **P2 — game-line model:** total model + distributions + market shrinkage + backtest to set
  σ's and `w(week)`.
- **P3 — prop model:** volume × efficiency + game-script + injury handling + per-market
  distributions + backtest/calibration.
- **P4 — producer + wire-up:** `generate_nfl` → `game_predictions`/`prop_predictions`; NFL
  board/grade passes; front-end logos; validate a past week; go live Week 1.

## Risks

- **Timeline (~2.5 weeks) with props doubling the build** — mitigated by reusing serving/grade
  infra and limiting to seven markets; if the runway slips, game lines + yardage props ship
  first, TD/anytime markets follow.
- **Injury/inactive data is a hard prop dependency** — dual source (nflverse + ESPN actives).
- **Week-1 cold start** — no 2026 data; volume/efficiency from last-season rates + game script;
  game lines lean on market shrinkage.
- **NFL `game_pk` matching** across ESPN, nflverse, and The Odds API — needs a reliable key
  scheme (the MLB date-boundary lesson applies).
- **TD/longshot market noise** — pass-TD and anytime-TD are low-count/binary and high-variance;
  looser calibration than the yardage markets.
